# AI-CAD Desktop — техническая документация

Версия 1.0 · 5 ноября 2026 года

## 1. Назначение и границы системы

AI-CAD Desktop — Windows desktop-приложение для параметрического 3D-моделирования с единым механизмом выполнения ручных и структурированных AI-команд. Приложение позволяет создавать эскизы и объёмные тела, изменять параметры ранее выполненных операций, просматривать геометрию, сохранять проект и экспортировать инженерную модель. Геометрию рассчитывает CadQuery/OCCT; LLM не является вычислителем размеров, объёмов или топологии.

Основной пользовательский сценарий — построение детали из эскиза, последующее добавление отверстия или другой операции, изменение исходного размера с перестроением зависимых элементов и сохранение результата. В отличие от одноразового генератора мешей, рабочая единица здесь — редактируемый граф параметрических операций.

Текущий код — инженерный прототип, а не сертифицированная промышленная CAD-система. Фактическая пригодность для производственных задач не подтверждена.

## 2. Функциональные возможности

В коде представлены эскизы на плоскостях XY, XZ, YZ и пользовательской плоскости, содержащие прямоугольники, окружности, полигоны, линии, дуги и открытые траектории. Объёмные операции: box, cylinder, sphere, extrude, revolve, loft, sweep; булевы операции union, cut, intersect; модификации transform, mirror, hole, shell, fillet, chamfer, linear_pattern, polar_pattern. Отдельные операции адресуют грань или ребро выбранного тела.

Параметры допускают ограниченные арифметические выражения и ссылки на глобальные числовые параметры. Изменение исходного узла инициирует перестроение графа. Предусмотрены Undo/Redo, компоненты и простые сборки, поиск взаимных пересечений, измерение вершин, импорт STEP, экспорт STEP/STL и предварительная проекция в PDF.

Реализация функций установлена по исходному коду и описаниям тестов; она не равнозначна подтверждению надёжности на произвольных промышленных моделях.

## 3. Архитектура и границы компонентов

Точка входа run.py запускает PySide6 UI. aicad/universal_ui.py организует рабочее окно, дерево операций, редакторы параметров и AI-панель. aicad/sketch_ui.py отвечает за редактирование эскиза. aicad/universal.py содержит Feature, Model, проверку параметров, перестроение и сохранение проекта. aicad/commands.py и aicad/universal_ai.py связывают ручные операции и AI-планы с общим исполнителем. aicad/importing.py отвечает за переносимую STEP/BREP-загрузку; aicad/inspection.py — за измерения и анализ; aicad/drawing.py — за предварительный PDF.

UI → проверка действия / декодирование AI-плана → Model → CadQuery/OCCT → валидированная геометрия → viewport / проект / экспорт.

Рабочие потоки QThread используются для вычислительно длительных операций. Операции выполняются над копиями состояния; при ошибке или устаревшем результате активный проект не должен заменяться.

## 4. Модель данных и параметрическое перестроение

Формат проекта v3 хранит глобальные параметры и упорядоченный список Feature. Каждый Feature имеет id, kind, name, params, refs, visible и source. refs ссылается на предшествующие узлы. source различает manual, ai и import. Геометрические OCP-объекты не сериализуются как произвольные Python-объекты: при загрузке формы строятся повторно.

Model.rebuild() последовательно валидирует узлы, разрешает параметры, получает формы зависимостей, выполняет CadQuery-операции и проверяет итоговые solids. Изменение раннего параметра требует пересчёта зависимых узлов. Для выражений используется ограниченный AST, а не eval: допустимы числа, ссылки на параметры, сложение, вычитание, умножение и деление. Обнаруживаются циклы зависимостей, нечисловые значения, деление на ноль и выход за диапазон.

Ограничения реализации: MAX_NODES=200, MAX_COORD=10000, максимальное число ссылок на узел — 8. Это технические ограничения текущего кода, а не целевые требования промышленной версии.

## 5. Геометрические алгоритмы

Для эскиза создаётся локальная система координат плоскости; замкнутые контуры передаются в операции extrude/revolve/loft, а открытые пути — в sweep. Булевы операции применяются к формам, построенным предыдущими узлами. Отверстия, скругления и фаски используют выбранные геометрические элементы либо структурированные селекторы. Результат считается допустимым, если форма валидна, содержит solid и имеет положительный объём.

В сборке компоненты сохраняют индивидуальные преобразования, а пересечения оцениваются попарно через геометрическое ядро. Реализована проверка геометрического наложения, но отсутствует решатель сборочных сопряжений и кинематики.

Стабильная идентификация граней после произвольного перестроения не решена. Выбор по индексам может изменять смысл при смене топологии; это риск для последовательных зависимых операций.

## 6. AI-подсистема и контракт команд

В проекте присутствуют Offline, Mistral, Cloud, Ollama и Auto. Offline обрабатывает ограниченные русскоязычные формулировки и структурированный JSON. Mistral и Cloud используют OpenAI-compatible chat API; Ollama — локальный HTTP endpoint. Облачная передача контекста требует согласия; секрет Mistral читается из MISTRAL_API_KEY.

Pipeline: текст запроса и сводка текущего графа → интерпретатор → JSON-план разрешённых операций → schema validation → выполнение на копии Model → проверка геометрии → commit либо rollback → сообщение пользователю. При некорректном ответе или CAD-ошибке предусмотрена ограниченная попытка исправления плана. Встроенные BREP-данные не передаются в LLM как бинарное содержимое.

LLM не выполняет Python-код и не имеет права напрямую изменять файлы проекта. Mock-интеграционные тесты подтверждают отдельные сценарии планирования и отката; реальная стабильность Mistral/Cloud/Ollama на внешнем API не подтверждена.

## 7. Интерфейс и пользовательские сценарии

Главное окно содержит дерево Feature, рабочий viewport, управление эскизами и операциями, редактор параметров, AI-панель и меню импорта/экспорта. В viewport предусмотрены вращение, масштабирование, выбор body/face/edge/vertex и измерение расстояния между вершинами. Отдельные действия создают операции по выбранным граням и рёбрам.

Сценарий A: пользователь создаёт эскиз 80×50 мм, выдавливает на 8 мм, добавляет отверстие, меняет ширину и проверяет перестроение. Сценарий B: пользователь вводит структурированный AI-план, проверяет изменение дерева, затем отправляет невалидный план и убеждается, что модель осталась прежней. Сценарий C: пользователь сохраняет JSON, открывает его повторно, экспортирует STEP/STL и проверяет наличие solid в импортированном STEP.

## 8. Хранение, импорт и экспорт

Основной проект сохраняется в JSON v3 с описанием параметров и операций. Поддерживается импорт более ранних форматов через legacy_part. Для STEP-импорта реализован переносимый узел import_brep: исходная форма кодируется в ограниченное по размеру сжатое представление BREP внутри проекта. Это обеспечивает переносимость, но увеличивает размер файла и требует проверки лимитов и недоверенного содержимого.

STEP и STL экспортируют видимые конечные геометрические результаты. STEP сохраняет инженерную геометрию, STL — сеточное представление. PDF является предварительным чертежом с проекцией рёбер; корректное удаление скрытых линий и производственные стандарты оформления пока не реализованы.

## 9. Надёжность и обработка ошибок

До изменения проекта проверяются тип операции, допустимые поля, ссылки, числовые диапазоны и геометрический результат. AI batch выполняется атомарно: если одна операция недопустима, исходное состояние должно сохраниться. QThread-операции не должны заменять модель, если пользователь уже открыл другой проект. Сетевые ошибки, невалидный JSON и недоступность LLM не должны блокировать ручное CAD-моделирование.

Текущие ограничения: отсутствие полноценного solver для ограничений эскизов; нестабильность адресации топологии после изменения формы; ограниченная сборочная логика; software mesh viewport; предварительный PDF; ограниченная offline grammar; не проверенный переносимый EXE.

## 10. Тестирование и критерии MVP

Последний предоставленный журнал Windows 10 фиксирует 96 passed, 12 subtests passed, 7 warnings для pytest, а также успешные отдельные unittest-наборы. Это историческое подтверждение для конкретного состояния файлов, а не доказательство успешной проверки текущего пакета. В том же журнале PyInstaller завершился ошибкой отсутствующих qtwebengine_locales.

MVP принимается по воспроизводимому сквозному сценарию: создание тела, зависимая операция, редактирование параметра, корректный rebuild, отклонение неверной AI-команды без изменения модели, Undo/Redo, save/reload, экспорт STEP/STL, запуск Offline без ключей. Для каждой проверки фиксируются входные параметры, ожидаемая геометрия, фактический результат и версии зависимостей.

Windows EXE принимается отдельно: чистая сборка onedir, smoke-test упакованного процесса, запуск на компьютере без Conda, проверка Qt-плагинов и OCCT DLL. Никакие результаты Windows-сборки в этой версии не объявляются успешными.

## 11. Сборка и эксплуатация

Поддерживаемая конфигурация исходного запуска: Windows 10/11 x64, Miniforge, Python 3.11, conda-forge cadquery и pyside6, requests, reportlab, pytest, pyinstaller, ezdxf, certifi. После активации aicad-universal приложение запускается командой python run.py, тесты — python -m pytest -q. Скрипт build_windows.ps1 выполняет проверки, сборку PyInstaller onedir и packaged smoke-test.

В данном пакете изменён только сценарий сборки: дополнительно исключены QtWebEngineCore, QtWebEngineWidgets, QtWebEngineQuick и QtWebChannel, не импортируемые непосредственно CAD UI. Это техническая гипотеза устранения прежней ошибки, требующая проверки на Windows. Для запуска на чужом компьютере переносится вся папка dist/AI-CAD, а не один EXE.

## 12. Структура исходников и развитие

Исходная структура: run.py; aicad/universal.py, universal_ai.py, universal_ui.py, commands.py, sketch_ui.py, importing.py, inspection.py, drawing.py, core.py, ai.py, project.py, ui.py; tests/; scripts/; demo_output/; build_windows.ps1. Legacy- и universal-модули сосуществуют ради совместимости.

Приоритеты после MVP: (1) достоверная Windows-сборка и диагностика; (2) стабилизация GUI и 3D-представления; (3) параметрический sketch constraint solver; (4) устойчивые топологические идентификаторы; (5) сборочные mates и кинематика; (6) стандартизованные чертежи; (7) нагрузочные испытания и тесты на реальных инженерных деталях. Развитие выполняется без удаления уже существующих функций.

## 13. Архитектурные схемы

Схема 1. Ручное моделирование: PySide6 UI → валидатор параметров → Model.add/update → Model.rebuild → CadQuery/OCCT → viewport → JSON/STEP/STL.

Схема 2. AI-моделирование: запрос → Offline/LLM adapter → JSON-команды → decode_plan → execute на копии Model → проверка solid → commit или rollback → UI.

Схема 3. Зависимости: глобальные параметры → sketch → extrude → hole → fillet → terminal solid. Изменение sketch требует пересчёта зависимых операций; ошибка пересчёта не должна повреждать последний валидный проект.

## 14. Пример проверяемого эксперимента

Вход: прямоугольный эскиз длиной 80 мм и шириной 50 мм, выдавливание на 8 мм. Базовый теоретический объём без отверстий — 32000 мм³. После изменения длины на 100 мм ожидаемый объём исходного прямоугольного тела — 40000 мм³; если добавлены отверстия и скругления, ожидаемый объём вычисляется отдельно с учётом их геометрии.

Проверка: построить базовое тело, сравнить вычисленный CadQuery объём с аналитическим; изменить длину, повторить сравнение; затем добавить отверстие и проверить уменьшение объёма; сохранить и открыть проект; убедиться в совпадении объёма и количества Feature. Указанные числа — аналитические контрольные значения, а не результаты проведённого запуска.

## 15. Формальная модель выполнения пакета CAD-команд

Пакет операций передаётся в `aicad.commands.execute(model, commands)` как список из 1–30 словарей. Исполнитель поддерживает четыре действия: `add`, `update`, `remove`, `set_parameter`. Для `add` проверяются `kind`, словарь `params`, список `refs`, допустимые поля и необязательный псевдоним `alias`. Псевдоним позволяет сослаться на узел, созданный ранее в том же пакете, без знания заранее генерируемого UUID. Для `update` разрешено изменять параметры, ссылки, имя и видимость существующего узла. Ссылки, заданные через псевдонимы, разрешаются до передачи в `Model.update`.

| Действие | Вход | Проверка | Результат |
|---|---|---|---|
| `add` | `kind`, `params`, `refs`, опционально `alias` | Известный тип, валидные параметры, существующие зависимости | Новый узел Feature и его ID |
| `update` | `id`, изменяемые поля | Узел существует; ссылки и геометрия допустимы | Перестроенная модель с сохранением ID |
| `remove` | `id` | Возможность удалить узел без нарушения зависимостей | Изменённый граф |
| `set_parameter` | `name`, `value` | Допустимое имя, числовое выражение, успешный rebuild | Пересчитанные зависимые узлы |

В начале выполнения фиксируются снимок параметров и Feature, а также стеки Undo/Redo. Каждая операция использует обычные методы `Model`, поэтому к ней применяются те же геометрические проверки, что и к ручным действиям. При исключении исполнитель восстанавливает исходный граф и стеки истории. Успешный пакет добавляется в историю как один шаг Undo. Восстановление пользовательского состояния не следует путать с транзакцией файловой системы: экспорт файлов выполняется отдельно.

Пример структурированного плана:

```json
{
  "commands": [
    {"action": "add", "kind": "box", "params": {"length": 80, "width": 50, "height": 8}, "alias": "base"},
    {"action": "add", "kind": "hole", "params": {"center": [20, 0, 0], "radius": 3, "depth": 8, "axis": "Z"}, "refs": ["base"]}
  ]
}
```

Это пример формата команды, а не обещание, что произвольная геометрическая комбинация допустима: положение отверстия и результат операции проверяются геометрическим ядром.

## 16. Контроль целостности параметрической модели

Параметрические выражения разбираются через ограниченный AST. Разрешены числовые константы, имена объявленных глобальных параметров, унарные знаки и арифметические операции `+`, `-`, `*`, `/`. Вызовы функций, доступ к атрибутам и произвольные выражения Python отклоняются. Для ссылок на глобальные параметры используется множество уже разрешаемых имён, что позволяет обнаружить циклы. Результат должен быть конечным числом в разрешённом диапазоне.

Для каждого Feature существенны его тип, параметры и ссылки на ранее созданные узлы. При перестроении графа операции выполняются в установленном порядке. Если исходная операция создаёт неверную форму, невалидное тело или геометрию нулевого объёма там, где ожидается solid, выполнение отклоняется. Проверка `Shape.isValid()` и положительного объёма — необходимые, но не исчерпывающие критерии пригодности детали для производства.

В текущей архитектуре топологические индексы граней и рёбер не являются устойчивыми идентификаторами при изменении геометрии. Поэтому операции `edge_fillet`, `edge_chamfer`, `face_shell`, `face_hole` требуют отдельного регрессионного контроля после изменения ранних узлов графа. До реализации устойчивого topological naming эти операции нельзя считать гарантированно сохраняющими инженерный смысл при любом перестроении.

## 17. Обработка сетевых AI-запросов и границы доверия

Облачный адаптер формирует сообщения из системного контракта CAD-команд, пользовательского текста и сериализованного графа модели. Перед отправкой требуется разрешение пользователя. При наличии импортированной BREP-геометрии её бинарное содержимое исключается из контекста и заменяется геометрическим описанием. Возвращённый ответ проходит JSON-декодирование, проверку набора полей, нормализацию действий и пробное исполнение на копии модели.

При ошибке плана предусмотрена ограниченная повторная попытка с сообщением об ошибке. Ошибка сети, авторизации, недоступность модели и недопустимый JSON не должны изменять CAD-проект. В режиме Offline сетевые обращения не требуются. Поддержка API-адаптера не является доказательством качества реального LLM: для каждого провайдера нужны отдельные испытания с зафиксированной моделью, датой и входными запросами.

## 19. Контрольные условия готовности MVP

MVP принимается после воспроизведения полного сценария: создать параметрическое тело, добавить зависимую операцию, изменить размер, подтвердить успешный rebuild, отклонить ошибочный AI-план без повреждения состояния, выполнить Undo/Redo, сохранить и загрузить проект, экспортировать STEP и STL. Автоматические тесты должны выполняться в фиксированном окружении, а интерактивный PySide6 UI — проверяться отдельно на Windows.

Для Windows-релиза необходимо зафиксировать версии Python, CadQuery, PySide6, OCP, PyInstaller, команду сборки, результат smoke-test и запуск на отдельном компьютере. Наличие скрипта `build_windows.ps1` само по себе не подтверждает работоспособность EXE.
