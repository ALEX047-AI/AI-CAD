# Архитектура AI-CAD Desktop

## 1. Общая схема

`PySide6 UI → управление проектом → исполнитель CAD-команд → параметрическая модель → CadQuery/OpenCascade → 3D-представление и экспорт`.

AI-подсистема подключается к исполнителю через структурированные операции. Модель языка не должна напрямую исполнять произвольный Python-код.

## 2. Модель данных

Основная реализация расположена в `aicad/universal.py`. Проект содержит глобальные параметры и упорядоченный список элементов (`Feature`). Каждый элемент описывает тип операции, параметры и ссылки на предшествующие элементы. Для сериализации используется версия схемы проекта, определённая исходным кодом.

Изменение параметра требует повторного построения зависимых элементов. Корректность результата определяется CAD-ядром, а не текстовым ответом AI.

## 3. CAD-операции

Геометрия создаётся средствами CadQuery и OpenCascade/OCP. Система должна проверять размеры, типы аргументов, существование ссылок, допустимость операции и корректность результирующего тела. Ошибка операции не должна оставлять частично изменённую модель.

## 4. Команды

Модуль `aicad/commands.py` выполняет разрешённые структурированные операции. При пакетной обработке ссылки на ранее созданные элементы могут передаваться через псевдонимы. Предварительная проверка `preview()` выполняет операции на отдельной копии модели и не должна изменять исходный проект.

## 5. AI-подсистема

`aicad/universal_ai.py` предоставляет интерфейс получения структурированных CAD-команд. В исходном проекте предусмотрены локальная обработка и адаптеры внешних поставщиков. Доступность облачных сервисов зависит от конфигурации и не подтверждается наличием адаптера.

Поток обработки: запрос пользователя → разбор → структурированная команда → валидация → CAD-исполнитель → проверка геометрии → отображение результата.

## 6. Интерфейс

PySide6 отвечает за взаимодействие с пользователем, дерево модели, ввод параметров и визуализацию. Длительные вычисления не должны блокировать интерфейс. Подключение предварительного просмотра непосредственно к GUI является отдельной задачей разработки.

## 7. Хранение и обмен

Формат проекта сохраняет параметры и историю операций; STEP/STL применяются для обмена геометрией. STEP/STL не заменяют параметрическую историю исходного проекта.

## 8. Испытания и ограничения

Необходимы отдельные проверки корректности геометрии, повторного открытия проекта, недопустимых команд, отката, GUI и Windows-сборки. Исторические результаты испытаний не следует выдавать за результаты текущего релиза. Подробности — в `TEST_REPORT.md` и `KNOWN_ISSUES.md`.
